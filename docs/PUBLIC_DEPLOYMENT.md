# Публичный сайт на Vercel и внутренний сервис в Docker

Статус по решению владельца от 2026-10-07: Vercel и дальнейшая публичная публикация отложены в [долгосрочный roadmap](ROADMAP.md#later). Текущий приоритет — внутренний Wiki и его baseline-first workflow. Публичный хостинг не является зависимостью или критерием приёмки внутреннего продукта. Инструкции Vercel ниже сохранены как справочник на будущее, не как текущее задание; возобновление требует отдельного поручения владельца. Существующие сборка и конфигурация не удаляются, настройки хостинга этим решением не меняются.

Один репозиторий поддерживает два независимых варианта запуска:

| Возможность | Публичный Vercel | Внутренний Docker |
| --- | --- | --- |
| Лендинг и объяснение подхода | Да | Да |
| Русские руководства | Да, отдельные HTML-страницы | Да, в интерфейсе Wiki |
| Синтетические примеры | Статические карточки | Учебный viewer |
| Авторизация и личный кабинет | Нет | Да |
| Загрузка `.e365` и приватные проекты | Нет | Да |
| IDE и рабочая среда разработки | Нет | Внутренний контур, в рамках реализованных возможностей |
| Backend, SMTP и приватное хранилище | Нет | Node.js-сервис и volume |

Публичный сайт не подключается к внутреннему сервису. Он не принимает файлы, не создаёт проекты и не запрашивает сессии. Статьи об IDE и разработке остаются образовательным материалом; исполняемой IDE в публичной сборке нет.

## Сборка и локальный просмотр

Нужен Node.js 22+.

```sh
npm ci
npm run build:public
npm run preview:public
# http://127.0.0.1:43172
```

`preview:public` заново собирает сайт и запускает локальный статический сервер только на loopback. Порт можно изменить через `PUBLIC_PREVIEW_PORT`. Это инструмент просмотра, он не входит в публикуемую сборку.

`tools/build-public.mjs` создаёт `.public` из явного списка источников:

- `web/index.html` — общий шаблон лендинга; сборка меняет навигацию и действия на публичные;
- `dist/articles.js` и `dist/developer-articles.js` — те же статьи, что во внутреннем сервисе;
- `lib/demo.mjs` — только синтетическая конфигурация учебного примера;
- общая тема, публичные стили и скрипт копирования примеров.

Каталог `.public` полностью пересоздаётся при сборке. Не храните в нём ручные правки или собственные файлы. В него не копируются `.env`, `.local`, серверные модули, API, личный кабинет, viewer/IDE, расширение VS Code и архивы конфигураций. `dist/data.json` сохраняет прежний пустой индекс. Сборка не читает `.env` и не требует SMTP или OAuth.

Адреса: `/`, `/guide/`, `/articles/`, `/articles/<id>/`, `/examples/`, `/examples/<service>-<code>/`. Статьи доступны сразу в HTML, JavaScript нужен только для кнопки копирования. Неизвестные и внутренние адреса возвращают 404; перенаправления всех запросов на лендинг нет.

## Настройка Vercel

1. Создайте проект Vercel из репозитория `netbka/elma_wiki`.
2. Для отдельного репозитория Wiki оставьте Root Directory корнем. Если подключён родительский репозиторий Elma, выберите `elma_wiki` и проверьте, что submodule доступен при сборке.
3. Framework Preset — **Other**. Build Command — `npm run build:public`. Output Directory — `.public`. Эти параметры уже заданы в `vercel.json`.
4. Используйте Node.js 22 или новее. Параметры почты, ELMA и авторизации в Vercel не нужны.
5. Создайте preview deployment и проверьте страницы. Публикация production выполняется владельцем проекта отдельно.

`vercel.json` задаёт только статическую сборку и HTTP-заголовки. Functions, API-прокси и backend rewrites не используются. CSP запрещает `fetch`, XHR и WebSocket через `connect-src 'none'`. `.vercelignore` исключает приватные каталоги, секреты, архивы и локальные артефакты из загрузки исходников.

Свойства `framework`, `buildCommand`, `outputDirectory` и `headers` описаны в [официальной документации Vercel](https://vercel.com/docs/project-configuration/vercel-json).

## Внутренний Docker

Используйте существующие `Dockerfile`, `compose.yaml` и приватный `.env.production` по README. Контейнер продолжает запускать `server.mjs`, сохраняет проекты в volume и обслуживает полную внутреннюю версию. Каталог `.public` не используется Docker-версией; Vercel и Docker не делят сессии или пользовательские данные.

## Проверки

```sh
npm run test:public
npm run test:public:browser
npm run verify
```

Первая проверка контролирует набор публикуемых файлов, удаление устаревших артефактов, ссылки и конфигурацию Vercel. Браузерная проверка читает лендинг, все статьи и примеры, проверяет мобильную вёрстку, копирование, клавиатуру и отсутствие backend-запросов. Она использует тот же `.public`, который предназначен для Vercel.

Эти проверки подтверждают локальную статическую сборку. Реальное развёртывание, домен и HTTPS Vercel проверяются после создания deployment.
