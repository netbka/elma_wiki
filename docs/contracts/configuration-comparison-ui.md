# Configuration comparison UI — D2 / #94

The Changes tab renders the Solution's persisted `sourceComparisons`. It selects the latest full capture by default and allows earlier comparisons to be reopened. These comparisons remain independent of review acceptance: the previous full capture may still be pending or closed. Partial uploads never become a full-capture base. First, unknown, different and ambiguous Source states expose no verified delta. Changed component fingerprints appear first; unchanged context is collapsed. The exact before/after captured originals remain downloadable. Fingerprints establish component differences, not native runtime impact.

Contextual handoff and composed-candidate delivery panels reuse `mountInstalledComparison`. History loading never starts a Target read. The user explicitly selects DEV2 and requests `compareInstalled`, with the exact candidate revision and connection. `reconcileInstalled` also only reads: the existing coordinator may bind an observed manual import only when read-back matches the approved exact candidate. Both actions retain server authorization, identity continuity, candidate freshness and unresolved-delivery guards. Synthetic test connections are visibly marked as exercises. No import or DEV write is initiated here.

The UI uses the contextual HTTP seam owned by the D2 HTTP task: `GET .../delivery?installed=true` and `POST .../delivery` with `{action, revision, connectionId}`. It never accepts client-provided installed-state evidence. The authenticated execution actor remains separate from shared content ownership.

Unknown base, drift, unresolved outcome, read failure and reconciled states are distinct. Only a `compared` record bound to the current candidate ID, SHA-256, revision and selected connection displays a deployment delta. A stored record is evidence at its observation time; it is not a claim about current live state. Refreshing history does not re-observe DEV2. Changed candidates require another explicit read. Lost responses disable further comparison/reconciliation until history is refreshed, with no replay. Business acceptance remains unestablished throughout.

Evidence: `node --test test/configuration-comparison-view.test.mjs` and `node tools/configuration-comparisons-browser-check.mjs`; eleven `configuration-comparisons--*` Storybook states use the production renderer and synthetic fixtures. No live environment or native acceptance is established by these checks.
