# ELMA Wiki

Самостоятельный сервис на Node.js: landing page, синтетическая демонстрация,
вход через GitHub, личные порталы из `.e365` или извлечённой конфигурации
в GitHub-репозитории. Интерфейс и 18 технических инструкций — на русском.

## Запуск

Нужен Node.js 22+. Для локальной работы регистрация OAuth не обязательна.

```sh
git clone https://github.com/netbka/elma_wiki.git
cd elma_wiki
npm ci
npm start
```

Откройте **http://127.0.0.1:43171**. На странице входа выберите локальный
кабинет, создайте портал и загрузите `.e365`. Showcase: `/p/showcase/`.
Раздел с примерами и инструкцией: `/guide`. Остановка: Ctrl+C.
`npm run dev` перезапускает сервер при изменении кода. Другой порт: `PORT`.

## GitHub OAuth App

Регистрация приложения выполняется владельцем аккаунта в
[GitHub Developer settings](https://github.com/settings/applications/new).
Используйте отдельные OAuth Apps для локального и внешнего сервиса.

| Настройка локального приложения | Значение |
|---|---|
| Application name | ELMA Wiki Local |
| Homepage URL | `http://127.0.0.1:43171` |
| Authorization callback URL | `http://127.0.0.1:43171/auth/github/callback` |

Скопируйте `.env.example` в `.env`, впишите Client ID и Client Secret,
затем перезапустите сервер. Секрет заполняется только на вашей машине.
Не коммитьте `.env`. Кнопка GitHub становится доступна после настройки.

Авторизация проверяет state и PKCE; сессия живёт до 8 часов. Токены и
сессии хранятся только в памяти. После перезапуска нужен повторный вход;
порталы остаются на диске. GitHub scope `repo` нужен для закрытых репозиториев
и предоставляет более широкие права, чем используемые сервисом операции:
сервис выполняет только чтение, не push и не изменения репозиториев.

## Что умеет разбор

- ZIP-контейнер `.e365`: `package.json`, сервисные ZIP или папки сервисов.
- `manifest.json`: сущности, namespace, code, сервисы и логические пути.
- Поля приложений/форм, контекст процесса, массивы настроек.
- Имена function, клиент/сервер, lifecycle, ссылки Context/ViewContext,
  RPC и структурные зависимости.
- Поиск поставщиков зависимостей среди решений одного окружения.
- Раздельные окружения и сравнение структурных индексов.
- Повторная загрузка одного code заменяет только это решение.
- Непрозрачный пакет `data` отмечается явно; расшифровки нет.

Максимум загрузки: 128 МБ, запись: 64 МБ, суммарная распаковка: 512 МБ,
число записей: 25 000. Вложенные ZIP читаются на уровне сервисов, не рекурсивно.
Код никогда не исполняется. Имена функций извлекаются эвристически;
индекс не заменяет TypeScript-компилятор, проверку платформы или аудит прав.
Пути в портале — рекомендуемые логические пути, а не созданный workspace.

## Репозиторий конфигурации

Войдите через GitHub, создайте портал, укажите `owner/repository` либо
`https://github.com/owner/repository`, найдите и выберите конфигурацию.
Поддерживаются `.e365` и извлечённые каталоги:

```text
configuration/
  package.json
  appViews/manifest.json
  appViews/records.json
  widgets/manifest.json
  widgets/form.json
```

Используется default branch на момент операции. Чтение через GitHub API,
без выполнения исходного кода. Если дерево обрезано API, загрузите файл.
Автоматического фонового обновления и webhook нет: повторите импорт вручную.
При извлечённой конфигурации читаются только `package.json` и папки сервисов
с собственным `manifest.json`; посторонние папки репозитория исключаются.
Указатели Git LFS и символические ссылки не поддерживаются: загрузите сам архив
или извлечённые файлы конфигурации.
Не помещайте приватную конфигурацию в публичные репозитории.

## CLI и API

CLI создаёт индекс в `.local/data.json`; после локального входа он доступен
в портале «Локальный импорт CLI». Файлы разбираются последовательно.

```sh
npm run import -- --server development ./exports/example.e365
```

API из браузера после входа (тот же origin и cookie сессии):

```js
const response = await fetch(`/p/${portalId}/api/import?server=development`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/octet-stream',
    'X-Elma-Wiki-Import': '1'
  },
  body: file
});
const report = await response.json();
```

Использование интерпретатора без HTTP:

```js
import fs from 'node:fs/promises';
import { interpret } from './lib/e365.mjs';
const { solution, entities } = await interpret(await fs.readFile('./example.e365'), 'development');
console.log(solution.code, entities.map(e => e.functions));
```

## Развёртывание

Контейнер предназначен для HTTPS reverse proxy. Перед запуском заполните
`.env`: production OAuth credentials, `PUBLIC_BASE_URL=https://wiki.example.com`,
`DISABLE_LOCAL_LOGIN=1`. Пример proxy: `deploy/Caddyfile.example`.
После изменения домена обновите Homepage URL и callback OAuth App.

```sh
docker compose up --build -d
docker compose logs -f wiki
```

Compose публикует порт только на loopback: `127.0.0.1:43171`. Обратный proxy
должен передавать исходный Host. Приложение допускает только настроенный Host.
Health check: `GET /healthz`. Постоянный том: `wiki-data`.
Файлы хранилища принадлежат пользователю `node` (UID 1000 в Docker image).
Перед подключением существующего bind mount настройте права на запись.

Для Node без контейнера укажите `HOST=0.0.0.0`, `PUBLIC_BASE_URL=https://…`
и `DISABLE_LOCAL_LOGIN=1`; внешняя привязка без этих настроек отклоняется.
Код обслуживает один процесс; горизонтальное масштабирование требует общих
сессий, очереди и хранилища. На этом этапе нет оплаты, тарифов, email,
аналитики, восстановления сессии и лимитов диска на пользователя.

## Данные и конфиденциальность

Репозиторий содержит **только код, универсальные инструкции и синтетический
showcase**. Начальный `dist/data.json` пуст. Нет реальных конфигураций,
внутренних адресов, имён компаний, пользователей и live-соединений.

Порталы сохраняются в `.local/portals/<uuid>/data.json`; владельцы —
в `.local/portals.json`. `.local`, `.env`, `.e365`, ZIP и логи исключены
из Git и Docker build context. Не включайте локальные хранилища в коммиты
или архивы публикации исходного кода. Резервную копию тома храните отдельно.

Исходные архивы, defaultValue, значения credentials, тела скриптов, runtime
и формулы не сохраняются. Структурный индекс всё равно может быть
конфиденциальным: имена объектов и полей принадлежат пользователю и защищены
проверкой владельца при каждом запросе. Оператор хостинга имеет доступ к диску.
Внешние запросы приложения — только GitHub OAuth/API по явному действию.
В демонстрации и локальной загрузке внешних запросов нет.

## Структура и проверки

```text
web/             landing, кабинет, вход, примеры и развёртывание
dist/            интерфейс технической вики, универсальные статьи, пустой индекс
lib/e365.mjs     ZIP-разбор и разрешённые структурные metadata
lib/auth.mjs     GitHub OAuth, PKCE, сессии
lib/github.mjs   чтение конфигураций из GitHub
lib/store.mjs    сохранение индекса
lib/portals.mjs  владение порталами
lib/demo.mjs     синтетический showcase
server.mjs       маршруты и проверка доступа
tools/import.mjs CLI загрузки
test/            синтетические fixtures, разбор, доступ, OAuth и GitHub
```

```sh
npm test
npm run verify
```

Тесты используют только синтетические данные и подменённые ответы GitHub;
они не подключаются к внешней платформе и не требуют секретов.
Landing calculator оценивает экономию по вводимым предположениям, не
показывает измеренные результаты клиентов.
