# Работа с ELMA Wiki

Это самостоятельный Node.js-сервис. Начните с README.md и lib/e365.mjs.
Не используйте данные или credentials из родительских каталогов.

- В Git допустимы только код, универсальная документация и синтетические fixtures.
- dist/data.json должен оставаться пустым; импортированные индексы — только .local.
- Не коммитьте .env, OAuth-токены, архивы конфигураций или реальные примеры.
- Внешняя сеть приложения ограничена GitHub OAuth и получением профиля; не добавляйте импорт репозиториев или live-подключения.
- Проверяйте владельца портала для каждого API и data.json, не полагайтесь на UUID.
- Не исполняйте загруженный код; извлекайте metadata по allowlist.
- UI на русском. Сохраняйте ограничения ZIP, отдельный проект на файл и атомарность создания/повторного разбора.
- npm test и npm run verify перед синхронизацией с origin.
- Не переносите .openai/hosting.json и identity другого сайта.

## Как агенту работать с экспортом

1. Прочитайте README.md, lib/project-parser.mjs и отчёт конкретного проекта. Не используйте родительские каталоги и чужие проекты как источник недостающей конфигурации.
2. Найдите сущность по service, namespace и code. archivePath — путь внутри файла; provenance.identity указывает запись manifest. Поля содержат путь и JSON pointer; functionSources различает client, server и process. module определяется namespace и служит группировкой, а не доказательством отдельного установленного модуля.
3. Скачайте полный оригинал владельца и распакуйте штатным CLI в отдельную приватную папку. Сохраните package.json, manifest, runtime, history, ресурсы и неизвестные части. Не собирайте пакет из очищенного индекса.
4. Для поля определите контекст: fields приложения, descriptor.fields формы, context процесса или settings[]. Проверьте Context.data, ViewContext.data, Namespace, Global и RPC. Поиск имён не доказывает привязку события: проверьте lifecycle и descriptor.template.
5. Прочитайте объявленные зависимости в исходном package.json. present-in-file — только структурное совпадение внутри файла; external-unverified требует проверки поставщика и совместимой версии отдельно. Не объединяйте проекты автоматически, не меняйте зависимые копии как будто они исходные определения.
6. Сделайте минимальное изменение в полном исходнике. Для скрипта согласуйте TypeScript, компиляцию, descriptor/runtime и manifest/history. Используйте инструкции script-roundtrip и file-update; для новых полей рецепт экспериментален до серверного испытания.
7. Проверьте статус решения целевой компании отдельно: package.json#/solution/isAuthor отражает происхождение загруженного файла. Отсутствие флага — неизвестно. Не угадывайте адреса, среду или возможность импорта.
8. Выполните структурные проверки, совместимую сборку, проверочный импорт и повторный экспорт только в явно разрешённой пользователем среде. Этот сервис не подключается к ELMA и не публикует изменения. Зафиксируйте конкретные проверки и ограничения, не обещайте production-готовность по JSON-check.

Оригинал, извлечённые части, подробные отчёты и ревизии сохраняются только в .local/projects или приватном volume. В публичный отчёт допустимы общие количества и классы ошибок; не включайте имена файлов/объектов, код, служебные значения или сведения об организации. Секреты не печатайте. Удаление и reparse должны проверять владельца; архивные пути никогда не используются как непосредственные пути хранения.
