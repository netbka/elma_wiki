Для разработчика и администратора

От npm-запуска до своего сервиса.

Исходный код, загрузка конфигураций, GitHub OAuth и самостоятельное развёртывание.

1. Локальный запуск

Нужен Node.js 22 или новее. После запуска откройте http://127.0.0.1:43171. Локальный кабинет работает без GitHub; импорт репозитория доступен после настройки OAuth.

git clone https://github.com/netbka/elma_wiki.git
cd elma_wiki
npm ci
npm start

Для другого порта задайте PORT. Режим разработки: npm run dev. Проверки: npm test и npm run verify.

2. Создайте GitHub OAuth App

Откройте GitHub → Developer settings → OAuth Apps → New OAuth App. Используйте отдельное приложение для локальной и production-установки.

  • Application name: ELMA Wiki Local.
  • Homepage URL: http://127.0.0.1:43171.
  • Authorization callback URL: http://127.0.0.1:43171/auth/github/callback.

После регистрации скопируйте .env.example в .env и впишите Client ID и Client Secret. Секрет заполняется только на сервере. .env исключён из Git. Перезапустите npm start.

PUBLIC_BASE_URL=http://127.0.0.1:43171
GITHUB_CLIENT_ID=YOUR_CLIENT_ID
GITHUB_CLIENT_SECRET=YOUR_CLIENT_SECRET

Вход проверяет state и PKCE. Scope read:user repo позволяет идентифицировать пользователя и читать закрытые репозитории; GitHub scope repo предоставляет более широкие права, хотя сервис выполняет только чтение. Сессии и токены хранятся в памяти: после перезапуска нужен новый вход.

3. Создайте портал из .e365

  1. Войдите и создайте портал в кабинете.
  2. Выберите окружение и файлы .e365.
  3. Дождитесь отчёта по каждому файлу. Если один файл ошибочный, ранее успешно разобранные остаются в каталоге.
  4. Откройте портал. Найдите модуль, сущность, поля, функции и объявленные зависимости.

CLI поддерживает локальную пакетную загрузку. После локального входа результат виден в портале «Локальный импорт CLI»:

npm run import -- --server development ./exports/example.e365
npm start

Логические пути в карточках помогают организовать рабочее дерево. Сервис не создаёт редактируемый workspace и не импортирует изменения в исходную платформу.

4. Репозиторий конфигурации

Войдите через GitHub, укажите ссылку и нажмите «Найти конфигурации». Можно выбрать .e365 или каталог с package.json и сервисными manifest.json. Для архива содержимое разбирается в памяти; для извлечённой конфигурации скачиваются файлы выбранного дерева. Чтение использует GitHub API, без запуска кода и git clone на сервере.

configuration/
  package.json
  appViews/manifest.json
  appViews/records.json
  widgets/manifest.json
  widgets/form.json

Сервис загружает конфигурацию из default branch на момент операции. Автоматической синхронизации и webhook нет: для обновления повторите импорт. Не коммитьте секретную конфигурацию в публичный репозиторий.

5. Примеры кода

Разработка ELMA365 через файлы: поля и формы, связи, проверенный цикл скриптов, матрица версий и E365 Workbench для VS Code. Установка расширения →

Запрос загрузки из страницы сервиса после входа:

const response = await fetch(`/p/${portalId}/api/import?server=development`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/octet-stream',
    'X-Elma-Wiki-Import': '1'
  },
  body: file
});
const report = await response.json();

Разбор архива без HTTP:

import fs from 'node:fs/promises';
import { interpret } from './lib/e365.mjs';

const result = await interpret(await fs.readFile('./example.e365'), 'development');
console.log(result.solution.code);
console.log(result.entities.map(e => [e.namespace, e.code, e.functions]));

Пример функции формы для учебного контекста:

async function validateForm(): Promise<boolean> {
  return Boolean(ViewContext.data.title);
}

SDK и сигнатуру обработчика сверяйте с версией платформы. Портал только индексирует объявления, не проверяет типы и не запускает эту функцию.

6. Docker и внешний доступ

docker compose up --build -d
docker compose logs -f wiki

По умолчанию порт контейнера опубликован на 127.0.0.1:43171. Настройте HTTPS reverse proxy. Для внешнего развёртывания задайте PUBLIC_BASE_URL, DISABLE_LOCAL_LOGIN=1 и production OAuth credentials. Callback должен соответствовать публичному адресу.

PUBLIC_BASE_URL=https://wiki.example.com
DISABLE_LOCAL_LOGIN=1
GITHUB_CLIENT_ID=YOUR_PRODUCTION_CLIENT_ID
GITHUB_CLIENT_SECRET=YOUR_PRODUCTION_CLIENT_SECRET

В Docker HOST=0.0.0.0 задан в compose. При внешнем bind приложение требует HTTPS URL и отключённый локальный вход. Пример reverse proxy находится в deploy/Caddyfile.example. Для health check используйте /healthz.

Том wiki-data хранит индексы и владельцев порталов. Резервируйте его, а не исходные архивы: архивы сервис не хранит. Это стартовый вариант для одного процесса Node.js; для нескольких инстансов нужны общее хранилище, общие сессии и очередь импорта.

7. Что сохраняется

Репозиторий содержит только код, универсальные инструкции и синтетическую демонстрацию. Локальные порталы лежат в .local или Docker volume и исключены из Git и build context. Индекс содержит имена объектов, схему полей, функции и ссылки. Он тоже может быть конфиденциальным, поэтому личные порталы проверяют владельца при каждом запросе.

Исходные архивы, значения credentials, defaultValue, тела скриптов, runtime и формулы не сохраняются. Токены GitHub остаются в памяти сервера. Внешние сетевые запросы выполняются только при входе и чтении выбранного репозитория GitHub. Аналитика, внешние шрифты и соединения с живой платформой отсутствуют.
