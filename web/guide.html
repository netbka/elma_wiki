От .e365 к приватной вики

1. Подготовьте экспорт

Экспортируйте решение штатным инструментом вашей платформы. Не изменяйте оригинальный архив. Войдите и выберите .e365 в «Мои проекты». Название сервера и адрес подключения не требуются.

2. Выберите задачу

Найти поле, изменить обработчик или подготовить обновление. Поиск работает по именам, кодам полей, функций и путям внутри этого файла. Карточка объекта показывает, где расположен исходный фрагмент. Предпросмотр отображает только текст.

В «Отчёте разбора» проверьте пропущенные части. Структурный индекс не доказывает корректность runtime, прав или импорта.

3. Работайте с полным оригиналом

Скачайте оригинал, распакуйте в отдельную приватную рабочую папку и используйте инструкции разработчика. Вики ничего не меняет в конфигурации. Повторный разбор использует тот же сохранённый файл; если он завершится ошибкой, прежний индекс останется доступным.

Запуск локально

git clone https://github.com/netbka/elma_wiki.git
cd elma_wiki
npm ci
npm start
# http://127.0.0.1:43171

# Каждый аргумент создаёт отдельный проект владельца local
npm run import -- ./solution.e365

Настройка без передачи секретов в чат

npm run setup
npm run doctor
# После настройки перезапустите npm start

# Для внешнего HTTPS-сервиса, когда выбран адрес:
npm run setup -- --production
npm run doctor -- --production
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production up -d --build

Команда setup запрашивает EMAIL_FROM и скрыто — EMAIL_CRED_KEY, пароль приложения почты. Секрет сохраняется только в приватном файле настройки. Существующий файл не перезаписывается.

doctor проверяет параметры и доступность локального хранилища, не печатая значения, секреты или содержимое проектов. Доставка писем и внешний HTTPS проверяются отдельно.

Compose хранит проекты в volume, отключает локальный вход и слушает только loopback хоста. Reverse proxy должен передавать Host, совпадающий с PUBLIC_BASE_URL. Перед обновлением резервируйте volume. Для остановки используйте docker compose down без удаления volume.

Вход по почте

GitHub отключён. Укажите EMAIL_FROM и EMAIL_CRED_KEY — пароль приложения почты. Для Mail.ru: SMTP_HOST=smtp.mail.ru, SMTP_PORT=465, SMTP_SSL_TLS=true. IMAP получает почту и не используется для отправки ключей.

Введите почту на странице входа, получите ключ и введите его. Ключ одноразовый, действует 72 часа; сессия после входа — 72 часа. Новый ключ отменяет предыдущий. После перезапуска сервиса запросите новый ключ. Локальный вход по умолчанию отключён; для разработки на loopback можно явно установить DISABLE_LOCAL_LOGIN=0.

Развёртывание

docker build -t e365-wiki .
docker run -d --name e365-wiki   --env-file .env.production   -p 127.0.0.1:43171:43171   -v e365-projects:/app/.local e365-wiki

# .env.production, вне Git:
HOST=0.0.0.0
PORT=43171
PUBLIC_BASE_URL=https://wiki.example.org
DISABLE_LOCAL_LOGIN=1
EMAIL_FROM=sender@example.org
EMAIL_CRED_KEY=YOUR_APP_PASSWORD
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_SSL_TLS=true

Перед контейнером нужен reverse proxy с HTTPS. Данные сохраняются в volume. Резервируйте всё приватное хранилище, ограничьте доступ к нему и храните резервные копии с той же защитой. Поддерживается один процесс сервиса: файловая очередь не является распределённой блокировкой. После перезапуска войдите заново; проекты сохраняются.

API: загрузка в своей сессии

const response = await fetch('/api/projects?filename=solution.e365', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/octet-stream',
    'X-Elma-Wiki-Request': '1'
  },
  body: file
});
if (!response.ok) throw new Error('Загрузка не завершена');
const project = await response.json();
location.href = '/p/' + project.id + '/';

Все операции с приватным проектом проверяют владельца. Оригинал: GET /api/projects/:id/original. Повторный разбор: POST /api/projects/:id/reparse. Удаление: DELETE /api/projects/:id. Изменяющие запросы требуют заголовок сервиса и тот же Origin.

Прежние порталы

Порталы предыдущего формата остаются доступны владельцам и помечены «Прежний формат». Если оригинал ранее не сохранялся, восстановление и повторный разбор для них недоступны. Чтобы получить новый проект, загрузите исходный .e365 отдельно.
